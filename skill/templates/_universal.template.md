# 跨 agent 全局通用规则

适用范围：所有 agent、所有项目，始终生效。即使未加载任何分类，本文件依然适用。
优先级：通用规则 > 分类规则。共用库是参考资产，不是规则。

## R1 意图门槛（95%）

- 把握 **< 95%** 时不得开工，先输出"未充分理解的部分"，可附 2–4 个选项。
- 未理解度涉及：目标、范围边界、验收标准、约束（技术/时间/格式）、取舍优先级。
- 信息缺失或存在多种可行解读 → 一次性问清再动手；理解充分后用一句话复述目标即可开工，不反复确认。
- 凭现有上下文可直接推断的，不问。
- **主对象 = "要做的是什么样的项目"**。项目类型尚未明确 → 必问，不得先动手。
- 项目类型已明确（知道做什么、要做）→ R1 视为通过，不再追问细节，转入检索共用库索引，按索引取用资产后开工。

## R2 不做附和的验证者

- 用户方案有误、自相矛盾、不可行或与实际信息冲突 → 直接指出并给出依据（位置/事实/后果），不因请求而附和。
- 仅在确有理由时反对；不抬杠、不注水。
- 用户被纠正后仍坚持 → 按其方案执行，同时标注风险点与可验证的代价。

## 语言

- 规则文件、规则正文、回复给用户的内容：**一律优先中文**。
- 例外：代码、命令、路径、标识符、API/报错原文、通用技术术语——保持原样，不硬译。
- 交付物自身有语言要求（代码注释、对外文档、指定语言的产物）时按交付物要求执行；规则与沟通仍用中文。

## 规则体系

- 分两层：**通用规则**（本文件）与**分类规则**（`categories/<名称>.md`，一个工作领域一个文件）。
- 分类 = 本次对话中用户要做的工作属于哪个领域（如前端、后端、数据、运维），按任务划分，不按工具划分。
- 读完本文件后先判断分类，然后**只读匹配的分类**；不相干分类不得读取。
- 一个项目跨多个分类 → 全部读取；冲突由 agent 按项目情况裁决，并说明取舍理由。
- 文件系统为准：分类文件可能已存在但未登记。判断分类时须重新扫描 `categories/`，发现未登记的先行登记再继续。
- 所有规则文件保持：精简、可执行、中文、面向 agent 阅读。

## 共用库

位置：`<LIB_DIR>`，总索引 `lib\index.md`。

**触发**（满足任一）：

- 用户说"放入共用库 / 存到共用库 / 记到共用库"。
- 本次对话已约定该产出要跨项目复用。

**未触发时**：不主动入库、不建立空登记行、不复制项目内已有内容。

**读取（检索顺序，硬性）**：

- 触发条件：**R1 已通过**——即已完成分类/项目类型判定，知道要做的是哪类项目并要开始做。R1 未通过（还不知道要做什么类型的项目）→ 先问，不检索。
- 检索不阻塞提问：R1 已通过但仍有实现细节待定，可同时检索索引并提问。
- 第一步：只读 `lib\index.md` → 匹配分类的 `_index.md` → 再按需读子类索引。**禁止**遍历 `lib\` 全目录、禁止批量读取资产文件。
- 第二步：仅在索引里命中可用条目时，才读取该条目指向的**具体文件**，且只读用到的那几个。
- 第三步：索引无命中 → 直接按现有理解开工，不因"可能库里有"而扩大检索范围。
- 检索结果与本次工作无关 → 不读、不引用、不在回复里罗列。
- 索引里状态为 `已过时` 的条目不读。

**入库流程**：

1. **整理**：不照抄原始内容。剥离项目专属信息（临时路径、凭据、单项目业务字段），改成脱离原对话也能独立看懂的资产：说明用途、关键参数、适用/不适用边界、用法要点。
2. **归类**：`lib\<分类>\<子类>\`，分类名与 `categories\` 保持一致；分类或子类不存在则新建目录并建 `_index.md`。
3. **命名**：小写英文短横线 + 用途，如 `frontend/style/dark-dashboard.md`。一个文件只装一件事。
4. **登记**：在该分类目录的 `_index.md` 追加一行（名称、路径、内容说明、来源、日期、状态）；文件在子类目录下时，同时更新子类的 `_index.md`；新分类同时在 `lib\index.md`「分类索引」加一行。
5. **回报**：说明归入哪个路径、抽掉了哪些项目专属内容、登记在哪张表。

**维护**：

- 替换旧版本 → 新建文件，旧文件状态改 `已过时` 并注明替代者；不原地覆盖。
- 不得删除他人登记过的资产；失效时标 `已过时` 并写原因。
- 入库为**复制**而非移动：项目内原文件保留。
- 文件的格式按内容定（md / 代码 / 图片等），文本类优先中文；代码、命令、标识符保持原样。

## 新建分类流程

1. 先扫 `<RULE_DIR>\categories\`，能复用就复用，不新建。
2. 复制 `_template.md` 为 `categories/<名称>.md`（小写英文短横线命名），填写范围与规则。
3. 在「登记表」加一行：反引号分类名、路径、一句话触发条件。
4. 与已有分类重叠 → 合并，不并列新增。
