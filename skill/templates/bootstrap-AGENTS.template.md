# 全局规则 · 引导（所有 agent、所有项目）

**本文件不含规则。** 它只做两件事：指向规则库，以及声明写入限制。

## 1. 规则库位置

所有 agent 规则与跨 agent 全局规则都存放于：

```
<RULE_DIR>
```

## 2. 写入策略（硬性）

- 任何 agent 写入或修改全局规则，**必须**改 `<RULE_DIR>` 下的文件。
- **禁止**把规则写进本文件或其他任何默认规则/记忆位置（本 `AGENTS.md`、项目 `AGENTS.md`、`CLAUDE.md`、各 agent 记忆库、聊天记录）。此类写入视为无效，不予承认。
- 引导文件 `AGENTS.md` 必须留在 `<harnessHome>` 才能被加载，无法放入规则库。它不含规则，因此不构成例外：所有规则内容归规则库所有。

## 3. 读取顺序（每轮）

1. `<RULE_DIR>\_universal.md` —— 跨 agent 通用规则 + 分类登记表。
2. 按登记表判断当前任务所属分类，**只读**匹配的分类文件。
3. 无匹配分类 → 在 `<RULE_DIR>\categories\` 下新建并登记到 `_universal.md`（见其中的登记流程）。

一个项目涉及多个分类 → 全部读取；冲突时由 agent 按项目情况裁决。不相干分类不得读取。

## 4. 共用库（可由 agent 写入）

- 位置：`<LIB_DIR>`，总索引 `<LIB_DIR>\index.md`。
- 用户说"放入共用库"时，按 `_universal.md` 的「共用库」章节整理、归类、登记后写入。
- 用户表达明确执行意图（R1 已通过：已明确要做什么类型的项目、要开工）时，先查索引（`index.md` → 分类 `_index.md` → 子类），命中才读具体文件；禁止全库扫描。项目类型未明确时先按 R1 提问，不检索。
- 除共用库外，规则文件仍只允许改 `<RULE_DIR>`。
